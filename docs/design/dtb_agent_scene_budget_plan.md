# Agent 专用自动场景预算方案（初稿）

2026-09-22 更新：system_prefix/native 运行时接口已由 Session A 实现，见
[部署与验收手册](dtb_system_routing_deployment.md)。本文保留 Opencode/run-06 的历史预算提案；
新交付的 Noemate 候选依据 Noemate 数据单列，不把本文 T500/T850 当成已验收的生产参数。

## 1. 设计目的与边界

设计日期：2026-09-11。源码起点为工作区 HEAD `0019df8`；实验依据为 Vanilla run-06、DTB run-06-closed（close+.90）及最低介入值 G1 回放。工作区未提交的其他设计/分析改动不作为已部署实现。

目标：在 Agent 专用服务中，请求只增加 `enable_think_budget=true`，即可使用适合 Agent 长尾思考分布的预算；保持任务质量和原生输出协议，争取稳定的 **>5% 任务聚合 LLM E2E 累计省时率**。标题、主/子 Agent 和重试请求全部计入，不再用 session 跨度裁决。>5% 是实际收益门槛，不等于统计显著。

本次只拟定预算、路由边界和验证顺序，**不创建可部署 YAML、不修改运行时、不执行服务器实验**。参数是待验收候选，不承诺配置后必然省时。

拟议独立制品：`dtb/config/budget_config_agent.yaml`，供 Agent 专用部署选择。它不合并现有问答/13产品场景规则，也不自动替换现有 `budget_config.yaml`。

实现细化见 [System场景规则与显式原生路由设计](dtb_system_scene_native_routing.md)：明确有界system/首user前缀规则、scene.action、拒识动作、serving原生分流与低成本遥测。本文预算值不因接口细化而改变。

依据：

- [run-06 原生分布与残余空间](../log/perf/agent_run06/RESULT.md#73-当前测试集的抓大放小空间)。
- [close+.90 质量与 LLM E2E 总账](../log/perf/agent_run06_closed/RESULT.md)。
- [G1 旁路与成本证据](../log/perf/agent_minimum_intervention/run_server_01/RESULT.md)。
- [最低介入值机制](dtb_minimum_intervention_threshold.md)。

本方案对旧 [泛化计划](think_budget_generalization_plan.md) 的变更限定为 **Agent 专用配置的分类输入**：不再只用最新 user 文本识别请求身份；原问答配置的路由语义保持原样，不引入另一套预算状态机。

## 2. 证据与预算选择逻辑

### 2.1 场景按当前请求用途划分，不按代码业务主题划分

当前通用分类器遍历配置中的全部规则，主要看最新 user 消息。Agent 请求携带的源码、需求、测试结果容易命中“检索/代码/故障”等主题，但这不代表当前请求在做什么。

用当前配置对 run-06-closed 的364条真实请求作离线自动预算推演：retrieval152条、code_generation108条、fault_diagnosis79条、general25条，对应T200/2000/500/200。9条标题也被分散到这些场景，而非识别为标题。这是离线路由结果，原实验实际使用固定T850，并未运行这些自动预算。

因此 v1 只引入两个预算场景：

- **agent_title**：生成会话标题，输出短、任务约束明确，是当前主要压缩收益来源。
- **agent_business**：主 Agent 评测编排及子 Agent 的分析/代码生成，统一保守预算。

主 Agent、patch分析子 Agent、代码生成子 Agent 可作为离线报告标签，但暂不分配不同预算：当前不足以证明不同角色的最优停止点，增加预算档数只会扩大未验证参数空间。不按case编号、文件名、当前成功/失败或耗时挑选运行时策略。

### 2.2 原生尾部空间

以下由 Vanilla run-06 已关联请求的 `metrics.reasoning_tokens_local` 复算；仅对391条有完整terminal的请求计算分布，无SSE的一条仍保留在任务时延账本。

| 请求用途 | 有效请求数 | reasoning合计 | T850：超阈值请求/尾部token | T500：超阈值请求/尾部token |
| --- | ---: | ---: | ---: | ---: |
| 标题 | 9 | 17,341 | 9 / 9,691 | 9 / 12,841 |
| 主 Agent | 321 | 26,014 | 1 / 1,035 | 8 / 2,603 |
| 子 Agent | 61 | 8,757 | 1 / 187 | 6 / 1,014 |

尾部定义为 `Σmax(0, L−T)`，是假定阈值后全部免费删除、后续输出不变时的乐观token空间，**不是预测省时**。

选择标题T500的依据：相对850，原生标题尾部空间增加3,150 token，原生超阈值标题仍为9条；实际新采样的触发率、置信度、probe次数和质量未知。业务若同时改T500，超阈值样本由2条扩大到14条，尾部只新增2,395 token，却增加12条潜在介入请求；当前没有证据证明这笔成本/风险值得承担。

### 2.3 已验证部分与尚未验证部分

close+.90/T850全量实验中，9标题累计E2E为244.876→141.500秒（省42.22%，103.377秒）；8标题实际介入，另一条原生自然完成，不能把全部差值都归因于DTB。全部reasoning减少9,754 token，其中标题贡献9,006（92.33%）。

同轮业务E2E多耗227.063秒，非reasoning输出增加38,919 token，全9任务仍变慢4.26%。两侧DT全通过集合省时3.92%，加Vanilla case35原始36/36证据为6.90%。因此标题是优先候选，但当前参数不是已通过全量非劣/时延验收的生产最优值。

G1已有480对回放和31条phase旁路证据，未显示大额稳定旁路开销；主回放缺明确off身份、存在首轮及输出长度差异，不等于零成本证明。本方案不重新将完整旁路性能实验设为前置主线，仅保留与新增分类路径相关的回归。

## 3. 候选预算

### 3.1 首选 A1 与一致性对照 A0

| 场景 | A0介入T | A1介入T | stride | num_thinking | min_think_tokens | prob_th | max_think_tokens |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| agent_title | 850 | **500** | 500 | 5 | 1 | .90 | 20,000 |
| agent_business | 850 | **850** | 500 | 5 | 1 | .90 | 20,000 |
| 上下文摘要助手 / 未识别 / 身份冲突 | 原生不介入 | 原生不介入 | — | — | — | — | 不施加DTB思考预算 |

- **A0**：自动路由/预算一致性对照，不是新优化候选。已识别请求的完整预算应与close+.90固定参数逐字段相同。
- **A1**：首个优化候选，只降低标题T。其他超参不同时改变，便于归因。
- min=1只允许首次probe不受额外最小思考门阻拦，**不会在第1个token触发probe**；仍须先达到T。
- 20,000是思考硬上限，不是标题输出上限，也不表示正常会生成这么长。v1保留它来对齐固定实验，不新设标题紧硬帽。
- num_thinking沿用现有状态机语义；不重新解释成独立的“最多5次probe”开关。
- 外部completion总额度沿用原请求/serving解析结果，样例为32,000；不降低它来获得表面省时。隐藏trial也必须单列模型工作量。
- 结构边界同delta优先、abort排空、自然结束抢先、无安全续写容量则不abort等规则完全复用当前介入状态机。

**共同算法冻结条件：**保留实验验证的 trial-close（追加 `</think>\n\n`）、trial上限50、原置信度聚合、Value-Min关闭、safety gate关闭。不复用trial答案，不改fresh-final，不改parser patch。

当前仓库 `generation_states.py` 的基础 `TRIAL_PROMPT` 没有close后缀；close是已有实验部署改动，不能只复制YAML就假定它存在。实现/部署时必须明确记录对应源码/patch hash；自动预算迁移与其他final-answer重构分开验收。YAML的 `check_answer_len` 当前不控制trial长度，不将它当作可调接口。

### 3.2 服务级默认配置约定

独立Agent文件保留完整服务配置所需的协议、观测等区块；`SCENES` 只保留两个预算场景、下述摘要助手原生动作场景和结构兼容所需的 `general` 节点，后者没有关键词。不包含问答主题规则。

接口细化后增加一个无预算的 `agent_context_summary` 原生动作节点：Vanilla case35存在一条明确的上下文摘要请求，没有证据支持将其套入标题或业务压缩预算。仍只有两档DTB预算，未知身份由general拒识原生。

| 项目 | 拟议值/语义 |
| --- | --- |
| RUNTIME.BUDGET_ENABLED | true |
| enable_scene_budget | true |
| enable_difficulty_estimator / enable_history_budget | false / false |
| scene_override | 空；不在全量自动验收中强制场景 |
| 全部RUNTIME.fixed_* | 0，包括fixed_budget_tokens、fixed_prob_th |
| RUNTIME.check_length / min_think_budget / think_stride / num_thinking | 850 / 1 / 500 / 5，防御性默认，不用于掩盖拒识 |
| RUNTIME.confidence_threshold | .95保留resolver哨兵默认；各场景通过prob_th=.90生效 |
| RUNTIME.max_thinking_tokens | 20,000，再受原生上下文/completion约束 |
| OBSERVABILITY.mode | 正式性能off；独立账本phase |
| general拒识动作 | 真正原生路径，不启动观察/压缩状态机，不使用默认预算继续probe |

RUNTIME不能填fixed_budget_tokens=20000来表达全局硬帽，否则会进入fixed分支，覆盖场景预算；用max_thinking_tokens及scene.max_think_tokens表达。请求中正值fixed_*同样会覆盖自动预算，因此自动验收必须核查实际代理请求体。

如果未来需要逐场景不同prob_th，RUNTIME.confidence_threshold应继续保留.95哨兵值；当前resolver会把非.95的RUNTIME阈值当作全局覆盖。

### 3.3 暂不纳入首轮的候选

- 标题T250：仅在T500实际净省时、格式与语义均不退化后再探索。Vanilla尾部上限再增2,250 token，不证明可安全删除。
- 标题stride缩短、trial10/20、prob_th继续降低：先不改。close轮12次probe中10次自然结束，全部probe仅17.449秒；收益机会不足以优先支持多轴搜索。
- 业务T500或按报告/代码阶段细分：需要真实阶段识别和独立质量数据，不能用历史故障代码上下文通过率替代Agent执行质量。
- 只优化标题、业务全部原生：可以作为之后的归因对照，但不是A1默认；当前先保留已测业务T850，避免同时改变两类请求行为。

## 4. 场景识别与配置接口边界

### 4.1 请求身份规则

独立文件减少遍历的规则集合，但**仅拆文件不能解决system身份不进入分类的问题**。实现阶段需为Agent配置增加有界、角色感知的身份提取，保留唯一运行时分类标识 `scene`，不新增必须串联的语义类别层。

第一版只识别真实日志中已存在的模板：

| 优先级 | scene | 请求身份依据 | 不使用的依据 |
| --- | --- | --- | --- |
| 1 | agent_title | system身份头明确为 `You are a title generator. You output ONLY a thread title. Nothing else.`，并有前置user指令 `Generate a title for this conversation:`；样本无工具声明，作为额外保守约束 | 最新user里的代码主题、标题措辞、case编号 |
| 2 | agent_business | system身份头明确为 `You are opencode, an interactive CLI tool that helps users with software engineering tasks.`，且不存在冲突的标题/其他身份指令 | tools非空、某个源码关键词、最近一次write/bash动作 |
| 拒识 | general | 缺少明确模板、模板变化、冲突、无法安全提取身份 | 不猜测“看起来像Agent” |

上表初稿基于真实样例。随后按接口设计对Vanilla392条/DTB364条做了全量离线身份核对：18条标题全部匹配，普通业务382/355条匹配；Vanilla余下1条为明确的上下文摘要助手，拟显式native。详见接口设计第6.1节。这不是新实现验收或holdout验证。身份匹配须限定真实消息角色与指令头位置，不在嵌套引文、工具结果、待概括材料内任意搜索；未验证的新模板先拒识。

标题system和前置user指令都是真实采集内容，不向模型prompt追加任何标签。业务场景包含主/子Agent；不依赖推理服务并未收到的LightCode task_id/session拓扑。

接口设计已选择在同一路由模块增加system_prefix匹配模式，直接消费有界身份视图，返回唯一scene与action；不再制造分类文本调用通用主题评分，预算仍只由现有resolver产生。不要把全部system+tools+历史拼成一个大字符串，也不能同时跑两套分类。

### 4.2 独立文件的加载与未实现项

现有loader接收显式路径，但默认controller固定加载 `budget_config.yaml`；不存在自动识别并加载 `budget_config_agent.yaml` 的生产开关。

第一版部署复用 [现有专用YAML部署方式](../../dtb/README.md#配置生命周期)：服务停止后备份规范文件，将Agent候选复制为规范 `budget_config.yaml`，记录源/目标SHA，再启动。不在运行中覆盖，不让一个进程按请求切换两份YAML，也不在本轮设计新增热加载或配置注册中心。原问答候选留存独立制品，由部署选择。

| 能力 | 当前状态 | 本方案要求 |
| --- | --- | --- |
| 独立SCENES映射、场景check_length作为介入T | 已支持 | 复用；仅缩小配置规则集合 |
| YAML启动加载、请求正值fixed覆盖 | 已支持 | 复用；自动实验清除fixed覆盖 |
| Agent角色感知身份提取 | 未支持完整方案 | 补充短身份视图；保持问答配置路径不变 |
| 拒识直接原生生成 | 当前拒识仍默认预算介入 | 补显式拒识动作及原生路径；不能以超大T或budget=0模拟 |
| 区分Agent/问答路由模式 | 当前没有专用schema开关 | 新接口设计确定ROUTING.mode=system_prefix/legacy_text；仍待实现并经loader验证 |
| close行为 | 已有服务器实验，不是YAML开关 | 核对并冻结部署实现，避免迁移时回到未close算法 |

这些能力仍待开发；新接口设计提供了明确标为“实现后才有效”的YAML片段，Agent专用文件必须在前置能力完成后成为部署候选。未知字段应由loader拒绝，不允许默默忽略。

未识别请求原生运行，是对整个特性的保守退出，不是悄悄删除性能样本。统计中继续保留其E2E，记录拒识率。当前目标环境是专用Agent服务，而不是在共享问答服务上全局改变拒识语义。

## 5. 验证与一致性检查

### 5.1 V0：离线路由与预算等价，不调用模型

1. 复用Vanilla-06全部392条、DTB-06-closed全部364条真实请求；以现有关联结果检查9标题/主子业务归属，不把这些离线标签注入线上请求。
2. 输出每请求scene、匹配证据、拒识原因、T、完整预算及source_by_field。全部已知标题应正确归类；普通业务不得被归入标题。
3. 增加负例：工具输出含标题指令、代码字符串含身份头、缺前置标题指令、冲突system、普通问答、未知Agent模板。不得因处理材料内容触发标题低阈值。
4. A0已识别请求与原fixed配置预算逐字段相等，包含min=1、.90、硬上限20,000；A1只允许标题check_length变为500。
5. 验证问答配置保持原行为；Agent配置未加载问答规则。测量新增分类CPU/输入长度，不凭规则少就宣称获得百分比E2E收益。
6. 固定流测试：T前边界、同delta边界优先、长工具正文、不支持切换、排空含边界、自然terminal抢先、额度不足、异常取消。非流式继续原状态机语义，本轮不宣称获得流式最低介入值收益。

### 5.2 V1：标题定向回放

复用全部9条标题真实输入，比较Vanilla、A0标题T850、A1标题T500；冻结其他算法及sampling参数。建议每输入每variant先6次，均衡执行顺序，预先规定warmup与cache条件；先跑off性能组，另取独立phase小样本核对预算/切换。

报告E2E累计差/逐输入差、TTFO、可见reasoning、completion、标题质量及全部协议异常；phase另记hidden probe、次数和prefill。标题质量包括贴合任务主题、非空、单行、满足原prompt长度/格式要求、无结构泄漏，不只检查字符数。无工具执行的标题回放不能代替业务编译/测试。

只有A1相对A0获得可重复净收益且无质量/协议退化，才进入全量。若失败，保留A0或原生，不用更低置信度掩盖T500不合适。

### 5.3 V2：自动模式全量验收

先用自动A0确认与固定参数部署等价，再执行A1与同身份Vanilla的3组全9任务实验；各组V/D顺序交替、单并发，全部轮次留存。新自动模式同时加入身份路由与不同标题T，因此不只与旧run-06单次Vanilla比较。

主指标：按task累加全部主/子/标题/重试请求E2E，再跨预先约定的完整轮次汇总。使用 [既定质量集合](../log/perf/agent_run06_closed/RESULT.md#61-指标与质量门定义)：全9任务总账、DTB非劣子集、两侧DT全通过子集，同时报告成员与任务数；全优/全合格只作敏感性分析。不同质量子集不能互相替代，不能只保留最好一轮。

验收要求：

- 已知请求身份正确；自动预算与预定scene一致；未识别请求原生并完整计入账本。
- 无新增协议hard failure；已有坏工具调用保留专项回归，最终DT通过不豁免过程协议错误。
- 全量报告任务质量转移，不用其他case改善抵消某case退化；重复中的随机退化单列分析，不以筛掉退化case宣告全量质量保持。
- 质量门成立后，固定全任务集合的累计LLM E2E目标>5%，同时报告各轮差异、任务等权收益和更快任务数。若只有严格全通过小子集达到，只能作子集结论。
- off正式性能与phase账本分开，部署清单包括模型/服务/patch/YAML/close实现hash、sampling、cache和代理日志开关。

### 5.4 收益空间边界

基线LLM E2E为2,902.455秒，5%约145.123秒。现有标题省103.377秒；**若业务完全持平**，还需约41.746秒净节省才能达到5%。这是情景算术，不是A1预测。

如果本轮业务额外227.063秒稳定复现，则从当前DTB总耗时达到基线95%还需再省268.809秒；当前全部标题耗时仅141.500秒，即使标题成本降为零也不够。届时应优先分析业务输出/修补轨迹，不继续把所有时延问题归因于标题T或probe成本。
