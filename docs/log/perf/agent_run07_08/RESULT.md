# Agent run-07 / run-08：关闭 telemetry 后的重复评测

分析日期：2026-09-14。结果提交：`e73d099`。基线为 Vanilla run-06；两轮DTB保留close＋.90及850介入阈值。本文所有百分比正数表示省时/减少。

## 1. 结论

**有：在明确的质量子集下，两轮均观察到超过5%的任务累计LLM E2E改善。最清晰的重复证据是固定case28、34最终DT均全通过，分别省时15.08%、19.19%。但不能把它扩展为“9任务各项质量均非劣”，也不能把相对旧run-06-closed的改善归因于关闭telemetry。**

- **实测，全9任务：**LLM E2E从Vanilla的2,902.455秒降到run-07的2,162.450秒（+25.50%）、run-08的2,566.697秒（+11.57%）。这两个总体数未通过逐任务质量非劣门。
- **固定最终DT全通过集合case28、34：**Vanilla 569.335秒，run-07 483.502秒、run-08 460.098秒；两轮平均471.800秒，相对同一个Vanilla省17.13%。两任务在两轮中分别都更快。平台start→end合计也分别省10.58%、11.55%。
- **固定可比DT非劣集合case3、28、34：**LLM分别省16.75%、9.33%；但run-07 case34先修补缺失import才全通过，评级由优秀降为良好。这里的非劣指最终评测DT结果，不指首次生成或所有质量维度。
- **再要求评级也非劣，固定case3、28：**两轮LLM分别省13.26%、6.25%，两轮平均省9.76%。case3不是两侧全通过：Vanilla14/15、run-07 15/15、run-08 14/15。若同时要求全通过且评级非劣，三方共同集合只剩case28，分别省8.35%、18.58%，仅一个任务不能泛化。
- **质量风险仍存在：**run-07 case35由Vanilla原始36/36退为编译失败；case37仅跑1条而非Vanilla的3条。run-08 case36由4/4退为3/4；case29用87条测试的98.85%不能直接与Vanilla8条的87.5%比较。
- **可用性：**649个DTB请求SSE/JSON/schema/终态离线审计未发现此前的空参数坏工具、非法工具名或协议尾流。run-08 case36仍有一次合法JSON但工具运行时拒绝的`task_id="code_gen_task"`，子Agent未启动，后续恢复。不能写成“所有工具执行零错误”。

## 3. 时间口径：LLM主指标与Excel平台时间

### 3.1 LLM E2E主指标

`L(variant, task) = Σ任务内全部请求 metrics.e2e_ms / 1000`，包括主Agent、子Agent、标题、失败和恢复请求。内部probe/prefill已包含在外部请求E2E中，不再重复相加。请求重叠仍相加，不估算session跨度。

集合省时率：`1 − ΣL(DTB) / ΣL(Vanilla)`。集合先由质量条件确定，不以时延大小选样本。补充任务等权相对收益、更快任务数和token账本见[cohorts.json](cohorts.json)。

### 4.1 不同“正确率”不能混用

- **正式报告记载的已执行DT全通过任务数：**Vanilla3/9、run-07 7/9、run-08 4/9。这里run-07包括case37的1/1，仅是报告内口径。
- **加入Vanilla case35原始36/36：**基线为4/9；run-08也是4/9，但通过集合发生转移（case36丢失、case2新增），总数持平不等于逐任务非劣。
- **保守地不计run-07 case37为完整测试成功：**run-07仍有6个任务的报告DT全通过，但不能因此忽略case35退化，也不能把未测项目直接当已通过或已失败。
- Vanilla case35仍缺报告与一次SSE，不补造评级；其36/36只用于显式标注的原始测试敏感性口径。Excel中该行0测试/N/A是缺报告的汇总结果，不能推翻session中的原始36/36，也不能按0/0算成功。

### 4.2 质量筛选规则

1. **评级非劣：**正式报告评级都存在，按不合格<合格<良好<优秀比较。允许两侧不合格，不等于成功；不自动覆盖测试范围变化。
2. **两侧全优 / 全合格：**分别为两侧评级均优秀 / 均≥合格。等级持平可能掩盖DT变动，合格条件也可能包含退化（如优秀→良好）。
3. **可比DT非劣：**两侧编译成功、报告测试类集合（规范化包名前缀）和测试总数相同，DT通过数不下降。排除run-07 case37、run-08 case29，避免分母变化。该筛选只证明报告覆盖范围相符，不证明测试源码/补丁字节相同或一次生成质量相同。
4. **两侧最终DT全通过：**在可比集合内，两侧全通过，无失败/错误/跳过；它是本任务最终评测口径。run-07 case34的修补时间全部保留，但必须标明首次生成/评级不是非劣。

## 6. 为什么这两轮能看到收益

### 6.1 正文/工具输出不再抵消思考节省

| 全9任务 | Vanilla | run-07 | run-08 |
| --- | ---: | ---: | ---: |
| 请求数 | 392 | 299 | 350 |
| 本地reasoning token | 52,112 | 29,922 | 39,759 |
| reasoning减少率 | — | 42.58% | 23.70% |
| completion token | 263,947 | 201,406 | 237,105 |
| completion减少率 | — | 23.69% | 10.17% |
| completion−reasoning | 211,835 | 171,484 | 197,346 |

相对上次run-06-closed正文/工具等非reasoning增加38,919 token，本轮该部分相对Vanilla分别减少40,351、14,489 token；思考减少也没有被抵消，响应总输出更少。这是直接可见的成本变化，而不是仅凭“关闭日志”解释性能差异。

但全量token下降也包含提前失败/缩小测试范围；不能全算有效压缩。固定全通过case28、34中，run-07 reasoning反而比Vanilla增加0.94%，completion却减少21.79%，LLM省15.08%；run-08 reasoning减少22.87%，completion减少23.42%，LLM省19.19%。**即使在最终DT全通过集合，正文/工具输出和执行轨迹变化也明显影响收益，不能全部归因给DTB缩短reasoning。**

### 6.2 标题与业务均有贡献

| 角色累计LLM秒 | Vanilla | run-07 | run-08 |
| --- | ---: | ---: | ---: |
| 标题（各9条） | 244.876 | 155.550 | 141.549 |

标题分别省89.327、103.327秒；业务主＋子合计分别省650.678、232.431秒。因此本轮正收益不只有标题。但run-07子Agent耗时反而增长，不能只读总和就推断所有阶段都优化。

### 6.3 telemetry off不能作为已证实的因果归因

**实测：**两轮off候选比旧Vanilla更快，也比run-06-closed phase-on候选更快。**尚未实测：**相同输入/相同采样轨迹、同部署下开关telemetry的净差额。两轮off之间LLM合计也相差404.247秒，且有显著正文、轮次、质量变化。

没有phase时，不推算hidden probe、真实介入率、child数、queue/prefill/decode或模型总工作量。completion不含hidden probe，本文只称“可见输出减少”。该缺口不影响客户端LLM E2E比较，但限制算法/日志开销归因。

## 7. 工具协议与运行时错误

已用原请求tools schema重建并审计run-07的376个、run-08的474个工具调用，未发现JSON/schema错误、未声明工具名、空参数坏工具、重复terminal、终态后尾流或预设整段prompt回显候选。SSE重建content/reasoning/usage与full-log逐请求一致。离线扫描未发现不等于证明所有潜在低频缺陷消失。

run-08 case36的主session记录一次task工具执行错误：

```text
call_id: call_32d3918e971346c6b9d80012
input.task_id: code_gen_task
error: Expected a string starting with "ses", got "code_gen_task"
```

这次输入是合法JSON；工具运行时要求已有session ID，模型却给了自造名称。关联器记录为未启动子Agent，后续任务继续，最终报告3/4。属于工具参数语义/运行时约束错误，不是已观察到parser丢参数。没有phase不能判断该请求是否发生DTB介入，也不能把最终标签测试失败归因于这次工具错误。恢复请求全部计入时延。

原始位置：[run-08 case36 session](../../../../lightcode/session_logs_dtb_08/task_2aaf4b0491f543a4_r1/logs/sessions/ses_f7076fe8affevrGtMrkd1IGyhs.json)，message `msg_08f8a8448001o3JGD2jb07pFRp`。Vanilla原有case35无SSE请求仍保留在异常账本，不能当成正常零输出。

## 8. 决策与下一轮
