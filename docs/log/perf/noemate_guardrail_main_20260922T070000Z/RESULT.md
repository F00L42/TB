当前适合冻结“750能够限制本轮可见思考长度”的机制结论，继续检验最终答案是否自包含、早退是否保留必要纠错，以及短路径的真实性能开销。无需再做完整池参数网格。

## 5. 质量边界：本轮已能定位的反例

参考答案评分按用户约定仍未执行。以下使用原始输入和确定算术做有限审阅，不使用Vanilla输出充当标准答案。可复核记录见 [semantic_checks.json](semantic_checks.json) 与 [long_output_evidence.md](long_output_evidence.md)。

### 178：思考里写过不等于用户得到完整答案

原始12条告警有4条严重项：ALM-2001/2004/2007/2010。DTB attempts **3、4、7、8、9、10** 的final全部只剩重要/次要8条，并从 `重要（Major）**` 开始。对应思考已列完严重组，并在下一组标题附近达到阈值；正文呈现为继续思考中的草稿。两部分合并虽然可能找齐12条，但**不能要求用户或下游从reasoning补全final**。

实测final ID覆盖：V 10/10包含12个ID，D仅4/10；V仍有4次length，故不把V的ID覆盖等同完整任务正确率。D的6次全部是stop、非空、自动协议绿灯，却有实质遗漏。反例请求示例：`dtbtool-l178-a3-dtb-main_20260922T070000Z_long_l178_measured`。

**假设：** 强制退出时的cue允许模型延续已经在思考里写出的草稿，没有确保final重新生成自包含答案。当前证据能确认遗漏，尚不能将所有遗漏归结为cue或parser的单一源码缺陷；需用固定输入的退出提示对照和必要的raw/token审计区分。不能通过把reasoning拼进content“修复”，也不能改变原生parser契约。

### 399：纠错尚未完成时退出，以及自然错误

输入四个值为92.641、88.315、71.253、85.792，Decimal复算总和 **338.001**、均值 **84.50025**。

- D/a1、D/a4输出错误总和 **337.999**；均值84.500的显示舍入本身并无错误，问题是总和。
- D/a2只复述4条数据，没有回答用户要求的总和/平均值。原prompt同时有“仅总结API原始数据”的约束冲突，因此该项记录为聚合任务未完成，区别于确定的算术错误。
- 其他7次D和10次V返回正确总和及精确/合理舍入均值。此为数值项核对，不是完整业务正确率（数据日期与“今日”仍有既有歧义）。
- **D/a1只有533 reasoning token，自然结束可能性高**；没有off账本，不能说它被750强制截断。D/a4为752，思考尾部停在重新验算的 `92.641+88.315=180.956; +71.2`，与截断纠错的风险相符。两者必须分开解释，不能说提高阈值就能治好全部错误。

750已证明能缩短思考，但对本场景不是已经验证安全的统一退出值。上轮phase两次数值正确不能推翻本轮反例。

上一轮提议的门是mean E2E额外耗时上界≤max(20ms,1% V均值)，不是用户已承诺SLA；即使用这个明确口径，8个case×sampling条件的E2E均未过门。区间宽意味着**不能证明非劣**，不等同于已证明控制器本身有秒级固定成本。

支持低固定开销的证据：

- 首输出8组单侧上界全部≤4.98ms，低于建议+10ms门；全样本均值差为−1.47至+2.37ms。这里是客户端首输出时间，不是内部prefill时间。
- 精确同输出（reasoning/content/工具名与参数一致，忽略随机tool ID）greedy14对平均差−2.30ms，原采样23对+1.56ms；合计37对+0.10ms。这是事后子集，只作机制开销的敏感性检查，不可替代全样本或逐案例置信界。
- A/A自己也高度不确定：4例的20对中同输出对数仅3、2、15、0。A/A平均差分别−528、+153、−210、−1311ms。更长reasoning/不同工具动作即使没有DTB也会发生，不能把greedy输出变化全部归为算法。

具体反例：原采样365的D有4/20次Rag，V为1/20；其余15对同输出平均只慢6.02ms。3次净增加的工具分支使全组平均慢282ms、P95从1.647s升到3.389s。对用户来说实际时延变化仍需报告；对源码归因，不能把这282ms叫做控制器CPU成本。

**选样边界也变了：** “短集合”是按上一轮Vanilla冻结的候选，不保证本轮每次都短。394的A/A有11/40次reasoning>750（最大1149）；321/394的其他组也出现越阈值。因此当前短集混有可能被干预的请求，不能直接作为纯观察路径开销测试。保留这些样本，不事后改名或删除以过门。

A/A发生于07:40–07:58 UTC左右，greedy A/B随后，原采样更晚；是连续分块而非交错A/A控制。无服务负载快照，不能从这些不同block精确扣除系统漂移。应报告两条独立结论：低固定开销得到支持；原业务采样下整体短请求非劣尚未成立。

下一轮应缩小问题，而非再跑相同610请求：

1. **语义主线先用178、399，319作收益保留样本。** 固定请求、原sampling及总completion额度，保留Vanilla对照。新增实验候选一次只改一个因素：可先用现有配置比较direct1024和direct750，检查是否给399留出纠错空间；若要检验178草稿续写，则另做“final明确要求从头给出完整、自包含答案”的cue候选，阈值仍750。cue候选尚未实现，不把它写成现有可用配置，也不同时更换阈值来混淆效果。
2. **建立极小、可审计的验收项。** 178的12条ID及级别必须完整出现在final；399显式核对总和/均值与是否真正回答问题；319由服务器本地模型按输入知识逐条审阅，再人工确认疑点。用户暂不做完整参考答案评测也不妨碍这些确定检查。不得仅用finish=stop作为通过。1024会减少2048额度下的final空间，不能保证改善353；不要单边增max_tokens制造收益。
3. **短路径单独诊断，优先21/365。** 使用H=budget=4096（高于原max_tokens=2048），确保本组不会因750阈值而接管；与Vanilla在交错独立block中重复，穿插A/A，记录实际sampling、服务身份和到达时间。保持MTP等环境不变。若greedy A/A仍大量分歧，先查目标服务的重复性/运行噪声；不能期待简单增加相同重复数就能辨明毫秒开销。所有输出保留，匹配输出仅作辅助。该对照只隔离观察路径，之后才恢复750验证真实行为分布。
4. **并发阶段的进入条件：** 退出策略不再发生178式final遗漏；边界算术有可接受且明确的质量结论；短路径开销与行为变化已有解释及预声明容差判断。达到这些条件后再做并发5，关注短请求P95、长请求占用和取消，不重新追求全池平均E2E最优。

现阶段已经有可用结论：“DTB能将这组长输入的可见思考控制在约750，并使319请求显著加速；当前直接退出策略存在答案完整性风险，短业务请求E2E非劣仍缺证据。”这不是实验白跑，也不是足以发布的质量非劣证明。
