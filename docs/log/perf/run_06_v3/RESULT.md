# run_06_v3 混合实验结果与自动策略收口建议

## 0. 结论

run_06_v3 同时测试了 7 个 fixed_v3 场景和 6 个仅传
`enable_think_budget=true` 的自动分类场景。结论如下：

- **实测——时延**：13/13 场景平均 E2E 均快于 Vanilla。633 请求加权平均由
  170.6025 s 降至 97.3737 s，改善 **73.2288 s / 42.92%**；场景等权宏平均
  paired gain 为 **88.7948 s / 45.78%**，597/633 个请求更快。
- **实测——质量**：run_06_v3 正确数为 555/633，Vanilla 为 558/633；严格逐场景
  非劣为 7/13。按本轮允许的“最多比 Vanilla 少 1 题”门
  `candidate_correct >= vanilla_correct - 1`，**11/13 场景通过**。未通过的是
  ReAct 白盒单步规划和事件自闭环，均比 Vanilla 少 3 题；但它们更早的 v2/v1
  分别只少 1 题，因此当前参数搜索总体已达到 **13/13 场景可选**。
- **实测——分类器**：6 个自动场景共 282/282 请求全部命中目标产品 scene，0 reject、
  0 误路由；四维预算、阈值和 hard limit 均与 frozen v2 一致，来源为 `scene` /
  `scene.max_think_tokens`。同轮其余 351 个 fixed_v3 请求全部命中 fixed 分支，来源和值
  与候选文件一致。
- **实测——动态模块**：633/633 使用最新 user message 分类；difficulty/history 参与数
  均为 0。没有客户端错误。服务日志中的 4 个非测试 parent/phase 被 request-id 白名单
  排除。
- **决策（2026-08-10 澄清）**：逐场景先选择正确率不低于 Vanilla 的候选并在该层
  比 E2E；只有严格层为空时才允许少 1 题层。按此规则，白盒单步规划从 v2 改为 v1，
  投诉工具调用从 v2 改为 v3，投诉分类中文从 v3 改为 v1；其余 10 个 scene 不变。
- **下一优先级**：13 个产品 scene 和新选择均已写入配置，运行 13 场景全部只传开关的
  run_07。reject/native bypass、history 和预算聚类继续后置。

## 5. 质量优先的参数选择

选择规则按以下顺序执行，不能跨层比较 E2E：

1. 质量严格层：`candidate_correct >= vanilla_correct`，若非空则只在本层选择平均
   E2E 最低者；
2. 一题容差层：仅当严格层为空时，允许
   `candidate_correct = vanilla_correct - 1`，并在本层选择平均 E2E 最低者；
3. 若两层均为空，则没有可发布候选，应继续搜索或 reject/native。

同一 scene 的正确样本数不能由其他 scene 抵消。6 个 run_06 自动 scene 没有新的
