# run_07：13 场景仅开启特性的自动分类验收

## 0. 结论

本轮 13 个产品测试集均只传入：

```text
enable_think_budget = true
```

没有传入任何 `fixed_*` 参数，且 history、difficulty 均未参与预算决策。

- **实测——自动分类通过**：633/633 个请求均由最新用户消息命中预期产品 `scene`，
  633/633 进入 `scene_difficulty` 分支并读取对应 scene 预算；`fixed`、reject、default、
  history 命中数均为 0。所有有效字段和值与 run_06 收口后的 13 组配置一致。
- **实测——时延目标通过**：相对 run_04 Vanilla，请求加权平均 E2E 从
  170.6025 s 降到 94.5468 s，降低 76.0558 s / **44.58%**；13 场景等权宏平均
  paired gain 为 97.6342 s，场景等权相对降幅为 **50.65%**。13/13 场景平均 E2E
  和 P95 均改善，606/633 个配对请求更快。
- **实测——预声明质量门通过**：将人工复核的唯一无效裁判
  `MAECOM00116` 记为错误后，run_07 与 Vanilla 均为 **558/633**。7 个场景进入
  严格非劣层，6 个场景恰好比 Vanilla 少 1 题，0 个场景低于预先声明的一题容差门。
  22 题由 Vanilla 正确变为 run_07 错误，另有 22 题反向改善，净变化为 0。
- **实测——隐藏成本已入账**：58,728 个 hidden probe token 和 5,170.796 s probe
  phase wall time 已计入；全部模型生成 token 为 937,389，而不是响应 usage 中的
  878,619 completion token。

因此，**“13 个已知产品测试集只开开关即可自动命中有效预算，并在一题容差质量门内
取得显著 E2E 收益”这一阶段一核心产品里程碑已经达成**。但按
[`think_budget_generalization_plan.md`](../../../design/think_budget_generalization_plan.md)
定义的完整阶段一验收，当前应记为**尚未完全达成**：run_07 仍是参与规则和参数选择的
同一批 633 条 search 样本，不是产品 holdout；通用/OOD、reject 行为、hard failure
专项审核和 profile 复杂度门也尚未完成。

当前 13 组运行时配置应冻结，不再用同一 search 集继续调参。下一步转向产品 holdout
和一次小型通用/OOD 验收；只有相同 scene 复测连续低于一题容差门时才重新打开局部参数
搜索。

## 5. 模型工作量与 phase 账本

| phase | calls | wall time | 账本占比 | generated token | token 占比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `initial_think` | 633 | 23,860.465 s | 39.91% | 400,850 | 42.76% |
| `iterative_think` | 1,253 | 21,638.282 s | 36.19% | 328,200 | 35.01% |
| `confidence_probe` | 1,628 | 5,170.796 s | 8.65% | 58,728 | 6.27% |
| `final_answer` | 633 | 9,106.304 s | 15.23% | 149,611 | 15.96% |
| `decision` | 633 | 10.636 s | 0.02% | 0 | 0% |
| **合计** | **4,780** | **59,786.483 s** | **100%** | **937,389** | **100%** |

4,147 个模型 generate phase 的 queue、prefill、decode 和 wall time 均有记录；633 个
`decision` 是 CPU phase，不具有模型 queue/prefill/decode。phase wall time 与客户端
总 E2E 相差 61.616 s / 0.103%，账本闭合良好。

Telemetry 中可见思考为 729,050 token，hidden probe 为 58,728，最终答案为
149,611，总模型生成量为 937,389。客户端 completion token 为 878,619；telemetry 的
`visible_think + final_answer` 为 878,661，两种可见计数相差 42 token / 0.0048%。该微小
计数差不影响收益结论，但后续 run 应继续保留两种计数并报告差值，不能用响应 usage
代替包含 hidden probe 的总模型工作量。

控制器的主要剩余成本不是 scene 分类：scene classifier 平均仅 16.635 ms，全部
`decision` phase 只占账本 0.02%；模型思考 phase 占 76.10%，hidden probe 另占
8.65%。后续若继续做算法性能优化，应优先减少无收益的迭代思考或 probe，而不是优化
字符串分类 CPU。

## 6. 阶段一进展判断

### 6.1 已经达成

- [x] 13 个产品 search 场景已有按质量优先规则冻结的预算；
- [x] 633/633 请求在只传开关时自动命中正确 scene 和对应预算；
- [x] 13/13 场景平均 E2E、P95 和宏平均 E2E 均有正收益；
- [x] 7 个场景严格质量非劣，另 6 个场景均只少 1 题，0 个低于预声明容差门；
- [x] 微平均质量为 558/633，与 Vanilla 相同；
- [x] 客户端错误为 0，唯一无效 Judge 已由人工裁决为错误；
- [x] hidden probe token、时间和 queue/prefill/decode 覆盖已进入账本。

这足以确认当前 13 个已知产品测试集的“开启即优化”路径成立，也说明分类器没有吞掉
fixed 搜索得到的收益。

### 6.2 完整阶段一仍缺少

- [ ] **产品 holdout**：当前 633 条样本既参与 scene 规则离线开发，也用于 run_07
  验收；尚未证明未见过的同场景表达仍能稳定路由并保持质量—时延收益。
- [ ] **通用/OOD 与 reject**：尚未用开源通用任务检查误命中、reject/default 的质量
  和时延；真正的 native bypass 按两阶段边界仍可留到阶段二。
- [ ] **hard failure 门**：当前确认客户端错误为 0，但尚未把所有新增错误按解析错误、
  工具错误和关键事实错误做专项标注。Judge 总分不能自动替代 hard-failure 审核。
- [ ] **复杂度门**：当前 13 个 scene 对应 13 个不同预算签名；尚未证明哪些近似预算
  可以在不改变质量层和 E2E 收益的前提下合并。产品时延目标优先，因此不应为了减少
  profile 数强行合并。
- [ ] **可复现实验清单**：缺少 `manifest.json`，跨 run 的 sampling/seed、服务源码、
  模型和 cache 状态尚不能核对。

据此，阶段状态应记录为：**核心产品里程碑通过；完整阶段一条件未全部满足**。不能把
run_07 描述为对陌生产品模板或通用任务的泛化证明。

## 7. 下一轮工作

1. **冻结当前分类规则和 13 组预算**。不再根据相同 633 条 search 样本调参，避免把
   跨 run 波动继续拟合进配置。
2. **准备真正的产品 holdout**：每个 scene 使用未参与 required anchor/预算选择的模板
   变体或新问题，并同时执行 Vanilla 与“仅开启特性”。先审计 route/reject 和实际预算，
   再验收逐场景一题容差门、宏平均 E2E 和 hard failure。
3. **执行一次小型开源通用/OOD 测试**：首先确认陌生任务不会误命中 13 个产品 scene，
   再记录当前 reject/default 路径的质量和性能；native bypass 的实现与正式验收留到
   阶段二。
4. **补最小 hard-failure 审核**：优先人工检查本轮 22 个 `Vanilla-only correct`
   样本以及 holdout 中所有新增错误，单列解析、工具调用和关键事实错误。
5. **补齐 manifest 后再解释跨轮变化**：固定 generation sampling/seed 和 Judge
   `temperature=0`，记录服务与 adapter commit、模型版本、到达节奏和 cache 状态。
6. **profile 合并后置**：只对数值接近的预算做离线候选；任何合并都必须重新经过
   holdout 质量门和 E2E 比较。若没有近似等收益合并，保留 13 个 scene 直达预算是可接受
   的产品优先选择。

下一轮不需要继续进行全量 fixed_v4 搜索。只有 holdout 中某个已正确路由的 scene
连续复测仍比 Vanilla 少 2 题及以上，才对该 scene 局部重新开启 fixed 搜索。

## 8. 证据强度

- 本文的客户端 E2E、Token、Judge/人工裁决、逐请求配对、scene、分支、有效预算、
  phase token 和时间均为**实测**。
- “自动模式与入选 fixed 参数在预算执行语义上一致”由 telemetry 和当前运行时配置
  共同支持，属于**实测 + 源码确定**。
- “跨轮正确数变化来自生成采样、服务状态或 Judge 波动”只是候选解释，属于**假设**；
  缺少 manifest 时不作原因裁决。
- 对未见模板、开源任务和 native bypass 的收益没有当前实测证据，不作泛化结论。
