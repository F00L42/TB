# run_12：量化增训权重 TP4 自动 DTB telemetry-off 全集

## 0. 结论

本轮在 W8A8 量化、特定场景思维链压缩语料增训权重上，手工把
[`budget_config_quant.yaml`](../../../../dtb/config/budget_config_quant.yaml) 替换为服务规范配置，
13 个场景只传 `enable_think_budget=true`，不传 fixed 参数并关闭 telemetry，共完成 633 条请求。
按前序实验约定，本报告把本轮视为 TP4，并以
[`run_08_quant&post_train`](../run_08_quant&post_train/RESULT.md) 的同权重 TP4 Vanilla 为主基线；
按用户要求不处理实验 manifest。

- **实测——总体 E2E 有正收益，但不是每场景开启即优化。** 请求加权平均 E2E 从
  77.1998 s 降至 **69.6709 s**，改善 **7.5289 s / 9.75%**；13 场景等权相对收益为
  **9.86%**，413/633 个配对请求更快。只有 8/13 个场景平均 E2E 改善；总体 P50 改善
  8.76%，P95 反而回退 **1.37%**。
- **实测——质量已基本恢复，但仍未通过逐场景门。** Vanilla / run_08 旧 DTB / run_12
  正确数为 **586 / 547 / 584**。Run_12 相比旧配置恢复 37 题，但白盒单步和 NetQAD 规划
  各比 Vanilla 少 2 题，超过“一场景最多少 1 题”的允许层；当前为 8 个严格层、3 个一题
  容差层、2 个失败层。
- **实测——fresh-final 与 2,048-token 截断问题在客户端结果上闭环。** 633/633 个模型回答
  非空、客户端错误为 0；历史截断样本 `TC00000069`、`YH0032` 分别生成 3,271、2,792 token，
  均被判正确。没有旧 2,048 cap，也没有再次出现空 final。
- **决策——不再继续 fixed 网格。** 白盒单步、机器数据、NetQAD 规划、告警建议和长文本根因
  五个场景的平均 E2E 均不如 Vanilla，其中前者和 NetQAD 规划还失败于质量门。下一步应实现
  **真正的逐场景 native bypass**，其余 8 个场景保留当前 DTB 参数。
- **离线反事实——“5 native + 8 DTB”比当前 13 DTB 更有希望。** 用同 QA_ID 的 Vanilla
  时延替换上述 5 场景后，组合估计为平均 68.6233 s、请求加权收益 11.11%、场景等权收益
  11.86%、P95 136.6359 s、正确数 588/633，且 13 场景均进入允许质量层。该结果不是服务器
  实测，只用于决定下一实现方向。

因此量化权重阶段一当前状态为：**全局时延门和 finalization 子目标通过，自动配置的逐场景
质量门未通过，且五个 scene 仍有负净收益；总体 P95 回退作为风险项继续跟踪。应转向 native
bypass 收口，而非 fixed_v6。**

## 1. 输入、实验身份与证据边界

权威输入：

- 客户端汇总：[`test_result/_SUMMARY.csv`](test_result/_SUMMARY.csv)；
- 客户端明细：`test_result/dtb_*.csv`，13 个文件、633 条请求；
- 主基线：run_08 中 13 个 `qp_vanilla_*.csv`；
- 历史旧配置参照：run_08 中 13 个 `qp_dtb_*.csv`。

实验身份按用户说明和前序约定处理：相同量化增训权重、TP4、手工启用量化 YAML、只开 DTB、
telemetry off。按用户要求不读取或要求补齐 `manifest.json`。这些身份属于**用户提供的实验事实**，
本文不进一步归因不同 commit、sampling、负载或 cache 的跨 run 波动。

目录虽然包含历史提取形式的 `extracted/`、`request_index.csv` 和 `extraction_manifest.json`，
但本轮声明关闭 telemetry，本文不使用这些文件，不把其中内容作为 run_12 的 phase 或分支证据。
因此本报告可以裁决客户端 E2E、最终回答、Judge 和 QA_ID 配对，不能裁决：

- 运行时实际 `decision_branch`、scene、预算签名或字段来源；
- visible thinking、hidden probe 和 final answer 的完整模型工作量；
- queue、prefill、decode 和控制器 phase 成本。

仓库中的量化配置和离线测试已证明同一批 633 条产品请求能够恢复 13 个目标 scene 与候选预算，
但这属于**源码/离线测试证据**，不能替代本轮运行时 telemetry。

## 3. 自动模式与预期配置

用户声明所有请求只传 DTB 开关，服务启动前已把量化 YAML 复制为 `budget_config.yaml`；因此
实验意图是让 `scene → budget` 自动恢复 5 个 fixed_v5 与 8 个 fixed_v4 候选。仓库离线测试
[`tests/test_dtb_scene_config.py`](../../../../tests/test_dtb_scene_config.py) 已对历史 633 条请求验证
预期 scene 和预算 633/633 命中。

本轮没有可用 telemetry，故以下两项必须分开表述：

- **部署/请求事实：**量化 YAML、只传开关、history/difficulty/telemetry 关闭；
- **运行时待证：**633 条请求是否全部实际进入 `scene_difficulty`，且是否逐字段使用该 YAML。

本轮 E2E 与质量足以决定当前配置是否可发布；缺少运行时分支证明只阻止“分类器已在服务器
命中 633/633”的表述，不改变两个质量失败场景和五个负收益场景的客户端事实。

## 6. 质量转移与失败样本

| 质量层 | 场景数 | 场景 |
| --- | ---: | --- |
| 严格非劣 | 8 | 机器数据、KPI、NetQAD 单步、告警建议、告警结论、投诉工具、投诉分类中英文 |
| 少 1 题 | 3 | 白盒整体、事件自闭环、长文本根因 |
| 少 2 题及以上 | 2 | 白盒单步、NetQAD 规划 |

总体正确数从 586/633 变为 584/633，微平均下降 0.32 pp；场景等权正确率从 93.50% 降为
92.65%，下降 0.85 pp。请求级转移为 Vanilla-only 21 条、run_12-only 19 条，净少 2 条。
总体缺口很小，但质量原则按场景生效，投诉分类中文多 4 题不能抵消两个场景各少 2 题。

失败场景的 Judge 原因没有出现无效或明显误裁签名：

- 白盒单步有 5 条 Vanilla 对→run_12 错、3 条反向改善。回退 ID 为 `TC00000006`、
  `TC00000007`、`TC00000011`、`TC00000024`、`TC00000057`，主要是 `valid`/API 约束错误、
  缺少实例化参数或在应停止自动化时继续执行；
- NetQAD 规划有 2 条回退、0 条改善：`TC00000015` 遗漏步骤 11～13，`TC00000016` 在人工
  操作后继续规划，均为任务核心约束错误。

因此当前没有依据做 Judge override。若要排除单轮生成波动，可只复测这两个场景一次；但它们
同时没有平均 E2E 收益，复测不会改变“优先 native、停止调参”的方向。

### 8.2 建议的最小下一步：5 native + 8 DTB

不构造 fixed_v6。为量化配置增加可验证的逐场景原生旁路，并让以下 scene 在分类命中后回到
原生单次生成：

1. `react_whitebox_single_step`；
2. `react_machine_data_analysis`；
3. `netqad_e2e_planning`；
4. `alarm_diagnosis_advice`；
5. `long_context_root_cause`。

其余 8 个 scene 保留当前 YAML 预算。native 必须绕过 DTB 状态机、probe 和 answer cue，不能用
大预算近似，也不能把 reject 后的默认 DTB 分支称为 native。

用 run_08 Vanilla 请求替换上述 5 场景的 run_12 请求，可得到以下**离线反事实**：

| 指标 | Vanilla | 当前 13 DTB | 估计 5 native + 8 DTB |
| --- | ---: | ---: | ---: |
| 请求加权平均 E2E | 77.1998 s | 69.6709 s | **68.6233 s** |
| 请求加权 E2E gain | — | 9.75% | **11.11%** |
| 场景等权相对 gain | — | 9.86% | **11.86%** |
| P50 / P95 | 65.7183 / 138.6804 s | 59.9581 / 140.5741 s | **59.7752 / 136.6359 s** |
| 正确数 | 586 | 584 | **588** |
| 严格 / 一题容差 / 失败 scene | 13 / 0 / 0 | 8 / 3 / 2 | **11 / 2 / 0** |

该估计只用于证明下一实现方向同时支配当前方案；真正结果仍需一次 TP4、telemetry-off、只传开关
的 13 场景全集。正式 run 之外可抽少量请求做 phase audit，确认 5 个 scene 走真实 native、
8 个 scene 恢复量化预算，但 phase run 不参与性能排名。

### 8.3 停止条件

- 若真实 hybrid 全集通过逐场景质量门且宏/微 E2E 为正，即冻结量化 YAML，不再搜索 fixed；
- 若 8 个保留 DTB scene 中仍有负平均收益或少 2 题，直接追加 native，不恢复全局参数搜索；
- 完成量化配置收口后，再开展 DTB × 量化增训权重包的受控价值比较。

## 9. 证据强度

- QA_ID 配对、客户端 E2E、P50/P95、Judge、错误、空 final 和两个长 final 为**实测**；
- TP4、量化增训权重、量化 YAML、只传开关和 telemetry off 为**用户提供的实验事实**；
