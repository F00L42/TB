# 性能分析
## 背景
有两套思维链压缩算法的工程实现：
* deer/AGENTS.md 介绍了思维链压缩模块集成在vllm 20.02版本中的实现（具体vllm源码位于/vllm-workspace/vllm）
* think_budget_vllm_adapter是一个基于deer的思维链控制接口实现的更加精细的控制算法，think_budget_refactored_final是这套算法的离线（API转发而不是服务集成）版本，算法实现可见think_budget_refactored_final/CLAUDE.md
docs/log/ 存放思维链压缩模块的执行信息，如服务器上的vllm日志、端到端测试结果
dtb.patch介绍压缩模块如何侵入式集成vllm，并可以通过请求参数控制开启或算法超参数
## 目标
思维链压缩实现的本质是额外计算和思考长度的tradeoff，最终时端到端延优化 = 少输出的Token数*TPOT - 最优思考长度估算和置信度校验实现的额外计算耗时
所以需要分析思维链压缩工程实现的优化空间，使后者尽可能低
### 建议
1. 在项目根目录创建AGENTS.md，初始化关键项目信息
2. 先基于简易版压缩算法的实现deer分析CoTController接口有哪些可以优化的部分，docs/log/test_results/_SUMMARY.csv中是两次端到端测试的结果，可以看到deer控制下输出的Token数少了，但是总时延却更高；docs/log/deer_confidence.txt是一次Deer请求的后台日志，附带打点输出置信度结果
3. 分析有哪些方便Agent读取的性能分析手段，可以人工去推理服务器环境代为执行（当前环境仅能访问源码和日志，无法真实运行vllm）
