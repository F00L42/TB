# 算法泛化性讨论
## 背景
AGENTS.md
docs/debug/deer_performance_analysis.md和docs/log/perf/run_02/RESULT.md等性能分析结果中可见，在固定超参的情况下在单场景稳定复现的端到端Token-2,511 / 55.48%，时延-20.5613 s / 31.48%，精度不下降（已补充语义质量分但暂未上传）的结果，但是用户不可能针对自己的场景去传一堆超参，这个特性的最终目标是开启即优化。
## 目标
已获取13个产品慢思考场景的测试集，需要在这些测试集上尽可能达成开启特性即可获得尽可能高的端到端时延优化，同时保证一定程度的通用任务（如使用开源测试机检验）泛化性
### 可用调试信息
可以回传源代码打点在服务器上的执行结果、提供端到端测试测试结果（每个具体测试集的时延、Token数、正确性的总览和每条结果，目前正在摸底测试）等runbook中提及的测试方法
### 优化思路
算法的基本流程在设计和开发中（docs/debug/think_budget_vllm_adapter_refactor_plan.md）确定，仍可以微调
如可以修改任务类型的匹配规则和已经记录的预设超参，通过多轮测试找到每个场景的使用超参，然后将它们绑定到细分任务类型上，但需要考虑对开源通用场景的影响
如可以使用历史难度估计功能，预先保存一些历史预算信息引导新任务使用已知的好参数
这部分逻辑主要在think_budget_vllm_adapter/budget_controller.py: 301 _decide中
以及任何你能想到的泛化性策略
最终输出泛化性实施讨论（如果对目标感到疑惑）或计划的文档
