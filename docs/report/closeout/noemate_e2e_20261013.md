# Noemate 思考预算实验：从 50 对长请求回放到完整端到端测试

整理日期：2026-10-13。本文是汇报的详细实验入口：演示第 4 页只保留一句“**端到端测试确认长请求加速，短请求非劣**”；需要展示分母、分层、请求记录、异常或归因依据时，使用本文和[冻结证据包](evidence/noemate_e2e_20261013/README.md)。

## 1. 本轮采纳什么结论

**在固定初始业务输入、同一份模型权重、正式 `observability=off` 的 Noemate 端到端运行中，启用思考预算后，过长思考尾部收敛，长请求变快，初始短请求性能非劣。** 这是本轮系统整体的观测验收结论，用户已确认实验输入固定并采纳此口径。

支持它的三组实测证据相互补充：

| 证据 | 结果 | 支撑什么 |
| --- | --- | --- |
| 全体主 Agent 模型调用 | 有效 reasoning >800：316/8,277 → 0/8,018；最大值 1,841 → 755 token；平均 E2E 14.971 → 10.685 s，P95 41.774 → 28.415 s | 整体运行中的过长思考收敛，平均和尾部模型调用时延下降 |
| 共同初始业务问题，按 Vanilla 自然思考长度固定分层 | 1,475 个短问题，9.361 → 6.752 s；DTB/Vanilla 比率 0.721，95% CI [0.700, 0.743] | 初始短调用未退化，本轮采纳为短请求性能非劣 |
| 共同初始长问题 | 8 个问题，34.001 → 10.045 s；8/8 更快，比率 0.295，95% CI [0.224, 0.400] | 固定业务输入的初始长层同样观察到加速，作为补充证据 |

这里的“端到端”测量边界是**网关视角的一次模型 HTTP 请求**：从调用到完整响应结束，覆盖该调用的等待、生成及返回。Noemate 确实完整运行了 Agent 闭环，但采集没有可靠的完整用户任务起止和工具 wall-time，因此不把上述秒数称为整项用户任务耗时。

“短请求非劣”限定为**本轮固定初始业务输入下的模型调用 E2E 性能**。它不表示每一条请求都更快、不表示业务质量非劣，也不是预注册退化 margin 后完成的正式非劣试验。运行日期、上下文和原生负对照的变化仍需保留，不能把所有改善解释为 DTB 单一因素造成的净收益。

## 2. 为什么要做完整运行，而不只回放长请求

DTB 的目标是以不退化的答案与协议换取净 E2E 收益。少生成可见思考只是手段；额外的隐藏 probe、重复 prefill、排队、置信度计算、预算判断、序列化和状态切换也会消耗时间。

此前的 50 对长请求回放说明选定长输入具备压缩与加速空间，但无法单独回答“部署到完整 Agent 流量之后，绝大多数短请求是否受到额外开销影响”。本轮从固定初始业务输入运行完整 Agent，保留后续工具选择、返回和多轮生成的真实行为，观察整体调用分布，再用共同初始问题检查短层表现。

固定初始业务输入是 Agent 系统试验的合理比较单位。系统输出、工具策略、记忆/偏好注入以及后续历史会随着运行变化；固定初始任务并不要求每一步生成后的完整 prompt 都逐字一致。本文接受前者作为整体运行验收口径，同时独立记录后者对“DTB 纯粹开关效应”的限制。

### 3.2 实际执行方法

用户确认了以下实验条件：

1. 所有初始业务输入固定；两轮使用同一份权重，模型服务别名差异不代表换模型。
2. 先开启 `phase`，确认思维链压缩功能正常。
3. 正式完整 E2E 已切回 `off`；phase 只做功能确认，不混入性能样本。
4. 通过透传网关给请求附加 `enable_think_budget=true` 执行本轮完整运行。

归档网关配置与有效请求相符：Vanilla 的 `append_body={}`；DTB 为 `{"enable_think_budget": true}`，未加 `fixed_*` 字段。主 Agent 两轮均 `temperature=0.2 / top_p=1 / stream=true`，未发送 seed。

| 请求类别 | Vanilla 参数 | 本轮 DTB 参数 |
| --- | --- | --- |
| main | 8,294 条 `max_tokens=2048`，12 条 `16384` | 8,028 条 `2048`，2 条 `16384` |
| followup | `max_tokens=1024 / temperature=0.7 / top_p=1`；thinking 关闭，非流式 | 相同，并附加开关；按场景仍走 native |
| compaction | `max_tokens=2048 / temperature=0.2 / top_p=1`，非流式 | 相同，并附加开关；按场景仍走 native |

源码默认 `enable_think_budget=false`，旧采集未发送该字段；新有效请求为 true。开关开启不意味着所有类别都压缩：Noemate main 使用预算路由，followup、compaction 使用原生路径。自动 Noemate 750 候选与请求级固定预算的优先关系见[部署手册](../../design/dtb_system_routing_deployment.md)。

网关 manifest 保存了 HTTP 采集配置、网关源码 commit 和 `httpx=0.28.1 / uvicorn=0.52.3 / transformers=5.5.4 / tokenizers=0.22.2`。它没有保存实际服务器 YAML、启动参数、模型修订 SHA、vLLM/Ascend/torch/torch-npu/CANN 身份。**同权重、正式 off、phase 验证及固定初始输入来自用户确认；它们不是从缺失的服务器 manifest 推测出来的。** 网关 `config_hash` 不能当成 DTB YAML hash。

两轮 capture 的 `repo_status` 都有未提交配置修改：Vanilla 修改网关 YAML；DTB 修改预算 YAML 和网关配置，并记录了候选配置删除及未跟踪运行目录。上表的 repo commit 只定位所记录的源码起点，不能当作“实际部署树完全干净且与提交逐字一致”的证明。原样身份保存在 `capture_conditions.json`，不据此补猜服务器配置。

两轮 tokenizer 归档目录和文件集合标识不同；本地 reasoning 长度沿用各自采集的 `local_reencode`。这本身不证明分词或权重改变。原生同输入子集的 API prompt token 完全相同提供了辅助一致性证据；尚未对全部文本独立校准。HTTP E2E 的比较不依赖本地重分词。

### 4.1 耗时和思考长度使用不同分母

主请求 E2E 描述统计保留全部 main 中记录了耗时的调用，包括 `length` 和解析异常：Vanilla 8,306、DTB 8,030。避免只留下成功且快速的请求。

思考分布只使用 `reasoning_tokens_local` 已知且 `exclusions=[]` 的可观察正常样本：Vanilla 8,277、DTB 8,018。不能把未知、截断或解析失败填成 0。

| main 思考分布排除项 | Vanilla | DTB |
| --- | ---: | ---: |
| `censored_or_other_finish`（main 均为 length） | 12 | 2 |
| `reasoning_unknown` | 16 | 8 |
| `parse_error` | 1 | 2 |
| 总计 / main 全部 | 29 / 8,306 | 12 / 8,030 |

这些是源账本标签。旧 followup 的 3,895 条和 compaction 的 11 条 `parse_error` 来自历史 null 字段解析缺陷；不能直接当作服务器输出失败。对应 HTTP200 完整响应的 content/usage 和耗时仍可用于原生延迟负对照，思考长度及质量则保持未知。

## 5. 全流量的过长思考和时延变化

### 5.1 可观察主请求的长尾收敛

| reasoning 指标 | Vanilla，n=8,277 | DTB，n=8,018 |
| --- | ---: | ---: |
| 平均 token | 280.62 | 243.19 |
| P50 | 207 | 183 |
| P95 | 753 | 689 |
| P99 | 1,002 | 752 |
| 最大值 | 1,841 | 755 |
| >750 | 415（5.01%） | 167（2.08%） |
| >800 | 316（3.82%） | 0（0%） |
| >1,000 | 83（1.00%） | 0（0%） |

DTB 的 167 条 >750 全部不超过 755，与阈值附近的 delta batch、abort/drain 边界现象一致。750 是预算候选，不是任意 token 上的精确硬切。选用 >800 检查明显超过阈值的尾部，避免将小幅越界与长思考失控混为一谈。

749–755 区间的新 main 有 287 条，这是公开思考长度在预算边界附近集中；**不是已审计的 287 次实际接管**。没有逐请求 phase 账本时，不能由本地长度反推出真实分支、child 数或 probe 工作量。用户先前的 phase smoke 用于确认功能生效，本次性能验收无需重开 phase。

该分布包含闭环中所有 main 调用，后续调用数量和历史不同，因此是整体系统观测，不把两组分布差等同于逐请求可安全删除的 token。

| --- | ---: | ---: | --- |
| 平均 E2E | 14.971 s | 10.685 s | 下降 28.63% |
| P50 E2E | 10.210 s | 7.790 s | 下降约 23.70% |
| P95 E2E | 41.774 s | 28.415 s | 下降约 31.98% |
| P99 E2E | 63.982 s | 42.699 s | 下降约 33.26% |
| 平均 TTFB | 2.792 s | 2.022 s | 下降约 27.58% |
| 平均 API prompt token | 32,236.52 | 31,781.92 | 调用集合和上下文不同 |
| 平均 API completion token | 453.22 | 390.23 | 不包含隐藏 probe |
| 请求到达时网关在途数均值 / P50，含自身 | 4.07 / 4 | 3.18 / 3 | 网关请求重叠，不是引擎配置并发 |

P50/P95/P99 使用 nearest-rank：排序后取 `ceil(n×p)` 的观测值。均值直接对当前全部 main 调用加权，不是业务问题等权，不给它伪造同输入配对 CI。

在途减少可能来自到达节奏或背景负载，也可能是请求更快结束后的结果。没有同配置的到达/cache/引擎账本时，不单独把它当成速度变化原因。MTP 维持生产默认，本轮不把它作为性能变量。

completion usage 下降只能描述公开 completion。它通常不计隐藏 probe，不能说“模型总生成工作量下降相同比例”。本轮未回传 phase 总账本，不估算真实总工作量或将缺失项填零。

## 6. 初始问题怎样配对、分层和计权

### 6.1 比较单位

用户确认所有初始业务输入固定。采集没有权威 QA_ID，本地复算采用完整的初始业务 user 原字符串作为稳定分组键，SHA256 前不做 `strip`、不删文字。

提取规则是：main 请求中找到第一个 user 消息，排除三个已知上下文前缀“以下为当前用户的偏好与特征”“以下内容来自用户长期记忆”“按如下内容开启技能”；`message_count = root_question_index + 1` 时，该 main 调用视为初始业务调用。CSV 的 question 最多展示 240 字符，**配对哈希由完整原串计算，预览截断不影响配对**。

| 初始覆盖 | Vanilla | DTB |
| --- | ---: | ---: |
| 初始 main 调用 | 1,875 | 1,875 |
| 含初始 main 的 session | 1,874 | 1,874 |
| 唯一初始业务问题原串 | 1,484 | 1,484 |
| 共同问题 | 两侧共同 1,483 个 | 两侧共同 1,483 个 |
| 共同问题覆盖的初始调用 | 1,874 / 1,875 | 1,874 / 1,875 |

一个 session 可以有多个初始调用，同一个业务问题也可重复。逐问题 CSV 明列 `vanilla_n / dtb_n`，不以行号配对，不把重复调用冒充更多独立问题；两侧各有 1 条没有共同原串的初始调用未进入共同问题比较。

### 6.2 用 Vanilla 长度固定分层

每个共同问题，用 Vanilla 的已记录初始 reasoning token 中位数确定层：≤750 为短，>750 为长；DTB 沿用同一层。另用 ≤512 的稳健短层检验结论是否依赖临近预算的样本。

不能分别用 Vanilla/DTB 各自实际输出长度分层：被 DTB 压短的长请求会进入 DTB 短层，造成处理后的分组偏差。后续生成出来的模型调用也不能自动继承其初始问题的“短”标签。

这是依据已完成两轮数据作出的固定基线分层，不是事先独立 pilot 和预注册的确认性设计。特别是初始长层只有 8 个问题、各 1 次调用，存在选中某次异常长输出后回归均值的可能。

### 6.3 重复调用先平均，问题再等权

时延比较只要求 HTTP200、`transport_status=completed`、正的有效 E2E；其余故障另列。reasoning 分布有效性采用上节 exclusions 规则，两者不互相代替。

对问题 `i`，先在每侧平均重复调用：

```text
V_i = mean(Vanilla 问题 i 的有效调用 E2E)
D_i = mean(DTB 问题 i 的有效调用 E2E)
R = mean_i(D_i) / mean_i(V_i)
降幅 = 1 - R
差值 = mean_i(D_i - V_i)
```

`R` 是两个等权均值的比率，不是逐问题比率的均值。重复次数多的问题不会获得更高业务权重。全 main 均值和初始问题等权均值有不同分母，必须分别列出。

同步 bootstrap 问题 case 5,000 次，seed=20261013。每次从同层的 `n` 个问题有放回抽取 `n` 个索引，两侧使用相同索引，重算均值比率和差值；CI 取 2.5%/97.5% percentile，端点在排序的重采样值间线性插值。

区间反映这两轮已观察 case 的抽样不确定性，不包含运行日期、配置、外部负载或上下文变化的不确定性。重采样同一批问题不能把历史运行变成随机交替开关试验。

## 7. 短请求非劣的实测依据

| Vanilla 预分层 | 共同问题 / 调用 V→D | 问题等权平均 E2E V→D | DTB/Vanilla [95% CI] | 更快问题数 |
| --- | ---: | ---: | ---: | ---: |
| ≤750 | 1,475 / 1,866→1,866 | 9.361→6.752 s | 0.721 [0.700, 0.743] | 1,089/1,475 |
| ≤512，稳健短层 | 1,444 / 1,822→1,822 | 9.093→6.715 s | 0.739 [0.717, 0.760] | 1,059/1,444 |
| 513–750 | 31 / 44→44 | 21.842→8.475 s | 0.388 [0.313, 0.481] | 30/31 |
| >750，初始长层 | 8 / 8→8 | 34.001→10.045 s | 0.295 [0.224, 0.400] | 8/8 |

短层平均快 27.87%，比率区间上界 0.743 <1；≤512 稳健层上界同样 <1。它比“差异不显著”提供更直接的证据：本轮观察均值没有向慢的一侧移动，且当前条件下的抽样区间整体位于 1 以下。

因此，本轮按用户采纳的整体观测口径结项为**短请求性能非劣**。有限样本不能证明每请求绝对零开销，也没有事前确定 5% 退化 margin；本文不把之前讨论的 5% 示例补写成真实执行过的标准。

短层同时有这些变化，必须和 E2E 一起公开：

| 短层辅助指标，问题等权 | Vanilla | DTB |
| --- | ---: | ---: |
| 平均 API prompt token | 17,346.83 | 16,419.00 |
| 平均 API completion token | 276.90 | 251.64 |
| 平均 reasoning token | 206.54 | 183.70 |
| 平均 TTFB | 1.978 s | 1.200 s |

固定初始业务输入下，实际模型 prompt 平均少约 928 token，约 5.35%；运行背景也变快。因此本节验证“打开功能后的整体运行没有拖慢初始短调用”，没有识别“相同完整 prompt 下 DTB 本体单独产生多少微秒开销”。所有问题的重复数、finish 及 token 数见[逐问题表](evidence/noemate_e2e_20261013/initial_root_cases.csv)。

均值性能非劣也不自动给出短层 P95 非劣。上面的 P95 来自全部 main 分布；若业务需要独立的短层尾延迟门，应单独确定统计量和业务界限。

## 9. 原生同输入负对照：为什么保留它

followup 在 Noemate 750 场景配置下为 native。两轮按完整实际请求配对，仅去掉已经确认等价的顶层 model 别名和 DTB/fixed 开关，不删 messages、工具或采样内容，得到 **114 个共同输入**，Vanilla 126 条、DTB 128 条。仍然重复先平均、case 等权。

| native 同输入指标 | Vanilla | DTB | DTB/Vanilla [95% CI] |
| --- | ---: | ---: | ---: |
| 平均 E2E | 2.988 s | 1.930 s | 0.646 [0.565, 0.736] |
| API prompt token | 344.395 | 344.395 | 1.000 [1.000, 1.000] |
| API completion token | 40.795 | 41.070 | 1.007 [0.971, 1.045] |

80/114 更快；同输入、相近输出长度的 native 调用也快了 35.39%。非流式 TTFB 接近整条响应耗时，不当成流式首 token。

这说明两轮存在运行背景改善，因而**不能将 main 短层的 27.87% 或全部 main 的 28.63% 全部归因于 DTB**。它与“开启功能的本轮整体运行没有拖慢短请求”并不矛盾：前者讨论收益的独立来源，后者讨论用户采纳的系统实测结果。

也不能直接用 `main 比率 / native 比率` 扣除背景，或据此宣布 DTB 慢了：两类调用的输入长度、生成和队列不同，平行趋势没有验证。保留负对照能避免过度归因，同时保持已完成 E2E 测试的价值。逐输入记录见[native 同输入表](evidence/noemate_e2e_20261013/native_same_input_cases.csv)。

## 10. 固定业务输入与完整模型输入的关系

两轮 main 的完整 `messages/tools` 或仅移除 model/预算开关后的请求哈希，交集都是 0。system 的核心业务规则、角色与工具说明一致：417 行，仅环境日期和 model 别名两行变化。只规范这两行并去掉顶层确认等价的 model，再保留全部记忆/偏好、历史、工具及采样，仍为 0 个共同完整 main 请求。

初始请求也可含不同的记忆/偏好消息；后续请求则自然继承各自生成与工具轨迹。不能再删除这些实际输入制造“同 prompt 配对”。这些哈希没有推翻用户确认的初始业务输入固定；它们明确系统级试验与逐请求同完整输入的估计对象不同。

本文因此使用三种比较，分别回答三个问题：

| 比较单位 | 可回答的问题 | 本轮处理 |
| --- | --- | --- |
| 全部 main 调用 | 完整系统运行后的长尾、均值、P95 是什么 | 两组描述统计，列明分母 |
| 相同初始业务问题 | 固定业务输入下，基线短/长问题的首次模型调用如何变化 | Vanilla 固定分层、重复平均、问题等权、同步 bootstrap |
| 相同完整 native 请求 | 背景运行是否也发生变化 | 114 个输入负对照 |

完整 system 哈希、运行字段规范规则和初始上下文审计见[system 差异](evidence/noemate_e2e_20261013/system_prompt_diff.json)。规范化只是辅助敏感性哈希，不修改原始消息或模型输入。

## 13. 从固定 Git 数据复算

本轮分析于 2026-10-13 在 Windows 本机离线完成，没有访问推理设备、重放模型、改 DTB 算法或重新分词。证据包重新直接读取两个固定源提交，保留全部请求的统计投影，而不复制完整 prompt/响应或 67 MB 中间 features。

只需 Python 标准库即可在仓库根目录复算：

```bash
python -X utf8 docs/report/closeout/evidence/noemate_e2e_20261013/recompute.py --verify
```

命令先核对冻结包 SHA，再重算五个统计子树、CI 和两个逐 case CSV，要求与归档逐值/逐字节一致；输出写入 `artifacts/perf/noemate_e2e_20261013_recomputed/`。若任何数值或文件哈希不同，直接失败，不静默跳过。

需要回到 Git blob 检查正文时，按对应 `*_features.manifest.json` 的 `source_commit/source_derived` 和 feature 的 `detail_path` 读取。每条记录带 `detail_git_blob/detail_sha256`，整个按 requests 顺序的 detail 集合也有汇总 SHA。重新生成完整统计投影的命令在[证据包说明](evidence/noemate_e2e_20261013/README.md)，无需恢复大目录。

`comparison.json` 保留先前分析的数值与严格因果/正式非劣 flags；`acceptance.json` 单独记录用户确认固定初始输入后采纳的系统整体观测结论。没有把观察数字改掉，也没有将历史分析的“纯 DTB 因果效应未识别”改成已证明。

## 14. 以后怎样把博客扩展为长期实验记录

本文已经成为演示的详细实验入口。后续实验继续按“身份与条件 → 完整性 → 固定输入与分层 → 请求级性能 → 长尾 → 协议/质量 → 因果边界 → 决策 → 命令与证据”追加独立 run，不把不同 run 的平均值拼成同条件因果结论。

如需提升到 DTB 单独开关的因果量或完整用户任务收益，补充下列证据即可；它们不是推翻本轮系统观测验收的前置条件：

- 同一运行环境，固定完整模型输入、sampling/seed、并发/到达/cache，随机交替 Vanilla/DTB，覆盖多个独立批次；用独立 Vanilla pilot 定长短层，避免单次长输出选样。
- 初始任务级可靠起止、工具 wall-time、重试、调用次数和业务成功；比较整体任务耗时和质量，而不是强配处理后已经变化的后续 prompt。
- 事前确定短层均值及尾延迟的业务退化界限，单列错误、截断和 invalid Judge；用置信上界判定，避免“差异不显著所以非劣”。
- 单独 phase 账本回合定位 budget 分支和 hidden probe/prefill/queue/token 总工作量，再切回 off 做正式排名；服务器 manifest 完整保存版本、源码、模型、YAML/patch hash。
- 对本轮两条空工具参数做原始流和实际 parser 追踪，补充协议与业务质量结论。

本轮可直接引用的结论保持为：**固定初始业务输入下，完整端到端运行观察到过长思考尾部收敛、长请求加速，初始短请求性能非劣。** 数值对应模型 HTTP E2E，独立归因和质量边界保留在本文。
