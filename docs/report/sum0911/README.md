## 维护和复算

修改技术博客后，同步邮件 Markdown 和 `sources/build_report.mjs` 中的展示文案，再重新生成 PPT。博客和邮件均只保留 Markdown，不生成 HTML。来源 SHA-256、逐任务指标、分布与案例 phase 保存在 [evidence.json](sources/evidence.json)。

`sources/collect_evidence.py` 只读已有实验数据，核对任务输入 hash、唯一请求 ID、请求与任务耗时总和、分档成员、原文片段及案例 phase，不调用模型。`sources/build_report.mjs` 使用已安装的 artifact-tool 生成原生数据图和四页 PPT，并运行包结构/版式校验。运行时路径按本工作区配置；跨机器需修改路径或使用同等运行时。每次先输出独立校验版本，再保存旧 PPT 到私有构建目录并更新交付文件。

`sources/build_editable_chart.mjs` 修复现有主 PPT 的散点连线兼容性，并生成独立统计图 PPTX 和预览。`repair_chart_markers.py` 在工作簿封装后移除样本数据点的线条覆盖，保留阈值与任务分界线。空心圆由外圈和白色中心两层原生标记构成，两层 X/Y 公式引用同一组工作簿单元格，编辑数据时同步更新；这不增加实际请求数。已检查 OOXML、内嵌数据引用和重新导入后的预览。

本次未新增目标服务器性能测试，也未发送邮件或发布网站。
