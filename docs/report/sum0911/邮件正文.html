DTB 阶段性汇报　2026.09　技术博客　邮件正文　展示 PPT

主题：DTB 阶段性进展：Agent 工程兼容完成定向验证，9 任务累计 LLM 耗时下降 11.57%

各位好，

本阶段围绕 DTB 接入 Agent 的工程可靠性与思考压缩效果开展了验证，主要进展如下。

一、解决多轮工具调用中的关键工程问题。 通过状态机与原生解析器协同修复，解决回合边界错位、工具前缀丢失、参数 JSON 不完整及停止条件误伤正文等问题。最新定向回放的 120 条响应未检出工具流协议异常，60 条 DTB 思考正文全部保真。后续完整 Agent run-08 也未检出已知协议故障，兼容方案不依赖关闭投机解码。模型工具选择和参数语义错误仍单独统计。

二、在总任务通过率持平的口径下，观察到时延与 reasoning token 双降。 9 个任务中，Vanilla run-06 与 DTB run-08 的最终 DT 全通过任务数均为 4/9；累计 LLM 端到端耗时从 2,902.455 秒降至 2,566.697 秒，减少 11.57%；可见 reasoning token 从 52,112 降至 39,759，减少 23.70%。平台执行时间合计减少 3.95%。通过率计入 Vanilla 一个缺报告任务的原始 36/36 测试证据；case36 退化、case2 改善，总数持平不代表逐任务非劣。这是历史基线上的实测差异，尚非严格因果或统计显著性证明。

策略上采用“抓大放小”：短请求保持原生完成，少数长思考才支付试答与重启成本。博客中以主 Agent 汇总测试结果的一轮说明：所需事实已经提取，模型仍在重复计数，DTB 早退后保留测试事实并继续报告流程。

三、下一步扩展到更多存在冗余思考的模型。 长度门槛、短试答与原生旁路的思路可以迁移，但每个模型都需重新适配协议、标定阈值，并用同身份 Vanilla 验证质量与净时延。当前跨模型收益尚待实测。近期将优先补齐同时期基线、固定测试范围和重复实验，再扩展模型。
