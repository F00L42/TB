---

### 🔍 核心原因分析
在FC SAN组网中，存储系统无法发现服务器Initiator（启动器）通常由以下原因导致：

| 原因类别 | 典型表现 |
|:---|:---|
| **Zone未放行** | FC交换机未将服务器HBA WWN与存储前端端口划入同一Zone，或Zone未激活 |
| **存储安全策略** | 部分存储默认隐藏未映射LUN的Initiator，需手动注册或先创建映射 |
| **HBA卡未就绪** | HP-UX未正确加载HBA驱动、固件不兼容、或WWN未被系统识别 |
| **多路径/扫描未触发** | 主机侧未执行SCSI总线扫描，存储端无交互流量故不显示在线状态 |

---

### 🛠️ 标准处理步骤

#### 1. 验证物理链路与Zone配置
- 登录FC交换机，使用 `show zone` 或 `cfgShow` 确认服务器HBA端口WWN与存储前端端口已在同一激活的Zone中。
- 检查端口链路状态：`show port` 确认双方端口均为 `Online` 且无CRC/信号衰减告警。

#### 2. 确认HP-UX侧HBA状态与WWN
```bash
# 查看HBA卡识别情况
lsdev -C | grep fc

# 查看WWN（以QLogic/Emulex为例）
fcmsutil -p /dev/fcs0 show  # 替换为实际设备节点
```
- 记录HBA的 **Node WWN** 与 **Port WWN**，确保与交换机上报一致。
- 若WWN显示为 `0000000000000000` 或设备未列出，检查驱动加载：`lsmod | grep <hba_driver>` 并重载固件。

#### 3. 存储端手动注册 Initiator
- 登录存储管理界面，进入 **主机管理 > Initiator列表**。
- 根据HP-UX HBA的Port WWN **手动创建Initiator**（部分存储需先创建主机组才能显示）。
- 若存储支持"自动发现"，确认该功能已启用且扫描周期已触发。

#### 4. 创建LUN映射并触发扫描
- 在存储侧将目标LUN映射给该HP-UX主机组。
- 返回HP-UX执行总线重新扫描：
```bash
# 刷新FC总线
ioscan -fnC disk
insf -e

# 若使用多路径软件（如PowerPath）
powermt save
powermt display
```
- 此时存储侧应显示Initiator状态为 `Online` 或 `已连接`。

---

### 📌 注意事项
- **安全策略差异**：企业级存储（如OceanStor、VMAX、USP等）默认遵循"零信任"原则，未授权Initiator即使链路通畅也不会广播上线。
- **固件兼容性**：HP-UX较老版本对新型HBA卡支持有限，建议核对HCL（硬件兼容列表）并升级HBA微码。
- **调试窗口建议**：涉及Zone调整或LUN重映射操作，建议安排在 **凌晨2:00～4:00** 话务低峰期执行，避免影响现网业务。

按上述流程操作后，90%以上的Initiator不可见问题可定位。若存储侧仍无响应，请提供交换机Zone配置截图、HP-UX `fcmsutil` 输出及存储型号，以便进一步分析。
