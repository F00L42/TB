### 🔍 可能原因
1. CHF端未下发对应的Trigger。
2. SMF本地未配置对应的Trigger。
3. Trigger的生效原则配置错误。

---

### 🛠️ 处理步骤

#### 1. 检查CHF是否下发对应的Trigger类型
查看用户跟踪消息，打开CHF给SMF返回的 `Charging Data Response [initial]` 或 `Charging Data Response [Update]` 消息，检查消息的 `triggers` 信元中是否包含了Session级或RG级对应的Trigger类型和属性。
- **是** → 进入步骤 3
- **否** → 进入步骤 2

#### 2. 检查SMF本地是否配置对应的Trigger类型
1. 在UNC上执行 `LST PDUTRIGGER` / `LST RGTRIGGER` 命令，查询SMF本地是否配置Session级或RG级的对应Trigger类型。
   - **是** → 进入步骤 3
   - **否** → 执行步骤 2.b
2. 在UNC上执行 `MOD PDUTRIGGER` / `MOD RGTRIGGER` 命令，本地按照规划配置Session级或RG级的对应Trigger类型。配置完成后，让用户再次访问触发对应Trigger上报的业务，观察SMF是否正常向CHF发送 `Charging Data Request [update]` 消息。
   - **正常** → 处理结束
   - **异常** → 进入步骤 3

#### 3. 检查Trigger的生效原则是否错误
Trigger生效原则说明：
- 如果Session级Trigger和RG级Trigger是完全不同的计费Trigger，按照各自的生效原则生效。
- 如果是Session级和RG级同时生效的计费Trigger，订阅存在冲突时，**以Session级Trigger的规则优先**（例如Session级为立即上报，RG级为延迟上报，则按立即上报处理）。

   - **否** → 进入步骤 3.2

   - **否** → 执行步骤 3.3
