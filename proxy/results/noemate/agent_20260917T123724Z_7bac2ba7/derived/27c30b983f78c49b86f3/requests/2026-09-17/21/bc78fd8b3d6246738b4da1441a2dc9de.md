**可自动清除**：是

### 告警触发机制
- NF实例化后向NRF发起注册，若连续失败次数超过`ADD NRFPARA`配置的最大重传次数（MAXRETRYTIMES），则切换NRF继续尝试。若所有NRF均注册失败，上报此告警。
- NF运行时心跳连续失败超过最大重传次数，触发重注册流程，所有NRF注册失败后上报此告警。

### 对系统的影响
NF无法被其他NF从NRF服务发现，**无法为新用户提供服务**。

---

## 可能原因及处理步骤

### 1. 常见失败原因
| 失败原因 | 说明 |
|:---|:---|
| GenerateRegPara failed | 注册参数生成失败 |
| SendHttpMsg failed | HTTP消息发送失败 |
| No NRF available | 无可用NRF |
| NRF is unreachable | NRF不可达 |
| Register Para Invalid | 注册参数不合法 |
| Data inconsistent between the NF and NRF | NF与NRF数据不一致 |
| AMF Has No Snssai Para | AMF缺少Snssai参数 |
| SmfInfo Has No Tai para | SMF缺少Tai参数 |
| 其他 | No RAN Access、Register Packet too large等 |

### 2. 处理流程

**步骤1：检查NRF返回码**
- 创建HTTP接口跟踪，查看NRF返回消息中的状态码：
  - **400 Bad Request** → 注册参数不合法，进入步骤2
  - **504 Gateway Time-out** → NRF超时，收集日志联系华为技术支持
  - **500 Internal Server Error** → NRF内部错误，收集日志联系华为技术支持

**步骤2：检查注册请求中的非法信元**
- 在HTTP跟踪中查看NRF返回的校验失败信元提示，例如：
```json

  "status": 400,
  "invalidParams": [
    \{"param": "/nFProfile/nfStatus", "reason": "The request inputs is not valid"\}
  ]
\}
```
- 根据提示修改对应的NF Profile信元值

**步骤3：修正后重新注册**
- 在NF侧执行`ACT NFONLINE`触发重新注册
- 观察注册是否成功，告警是否清除

**步骤4：数据不一致场景**
- 若失败原因为`Data inconsistent between the NF and NRF`：
  - 等待周期性数据核查结果一致时自动恢复，或
  - 手动执行`TST NFPROFILECHECK`触发数据核查

**步骤5：链路故障排查**
- 若其他NF也存在相同告警 → 可能是NRF侧故障
- 若仅个别NF告警 → 检查该NF与NRF之间的链路连通性
