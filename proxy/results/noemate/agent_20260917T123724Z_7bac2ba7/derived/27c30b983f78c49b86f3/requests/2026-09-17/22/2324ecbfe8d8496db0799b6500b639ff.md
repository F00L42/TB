PFCP会话管理流程主要包括以下三种核心流程：
* **PFCP会话建立流程**
* **PFCP会话修改流程**
* **PFCP会话释放流程**

以下是各流程的详细说明：

### 1. PFCP会话建立流程
用于在UPF上为PDU会话创建初始的PFCP会话上下文。
* **触发条件**：SMF收到建立新的PDU会话的触发请求。
* **信令交互**：
  1. **SMF → UPF**：发送 `PFCP Session Establishment Request` 消息。SMF分配一个新的PFCP会话标识（PFCP Session ID）并提供给UPF，该ID用于后续信令交互中标识PFCP会话上下文。消息中携带的关键信元包括：
     * **PDR (Packet Detection Rule)**：包含PDR ID、优先级（Precedence）、包检测信息（PDI），用于匹配进入的报文。
     * **FAR (Forwarding Action Rule)**：包含FAR ID、应用动作（Apply Action）、转发参数（Forwarding Parameters），指示对数据包的转发或丢弃动作。
     * **QER (QoS Enforcement Rule)**：包含QER ID、门控状态（Gate Status）、QoS Flow Identifier，用于QoS策略执行。
     * **Measurement**：指示测量方法（流量/时长/事件）、上报触发条件（周期/阈值）及测量信息。
  2. **UPF → SMF**：返回 `PFCP Session Establishment Response` 消息，携带接受或拒绝的原因值，以及UPF分配的会话标识等信息。
  3. **后续处理**：SMF与AMF或PCF交互，完成后续会话建立等业务流程。

### 2. PFCP会话修改流程
用于更新UPF上已有的PFCP会话上下文（如QoS策略变更、隧道地址变更等）。
* **触发条件**：网络侧或UE侧触发PDU会话参数变更。
* **信令交互**：
  1. **SMF → UPF**：发送 `PFCP Session Modification Request` 消息，携带需要新增、修改或删除的规则（PDR/FAR/QER等）。
  2. **UPF → SMF**：返回 `PFCP Session Modification Response` 消息，确认修改结果。
  3. **后续处理**：SMF与相关网元交互完成会话修改流程。

### 3. PFCP会话释放流程
用于删除UPF上已有PDU会话的PFCP会话上下文。
* **触发条件**：SMF收到删除PDU会话的触发请求。
* **信令交互**：
  1. **SMF → UPF**：发送 `PFCP Session Deletion Request` 消息。
  2. **UPF → SMF**：UPF通过PFCP会话ID识别并删除整个会话上下文，返回 `PFCP Session Deletion Response` 消息，携带接受或拒绝的原因值。
  3. **后续处理**：SMF与AMF或PCF交互，完成后续会话删除等业务流程。

### 补充说明
* **PFCP会话级别上报流程**：UPF可根据配置的上报触发条件（如流量阈值、时间阈值、周期上报等）向SMF上报用户面测量数据或事件。
* 所有PFCP会话管理流程均由控制面的SMF主导发起，UPF负责执行具体的用户面规则配置与状态维护。
