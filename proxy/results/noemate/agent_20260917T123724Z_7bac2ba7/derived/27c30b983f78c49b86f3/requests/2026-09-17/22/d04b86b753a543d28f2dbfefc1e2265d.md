### 1. 控制网元差异
* **4G网络**：会话管理功能分散在 `MME`、`S-GW` 和 `P-GW` 多个网元中协同完成。
* **5G网络**：会话管理由 `SMF`（会话管理功能）集中完成。SMF 聚合了 4G 中 MME 的会话管理模块以及 S-GW/P-GW 的控制面功能，架构更加简洁解耦。

### 2. 核心概念与QoS粒度对比
| 对比项 | 4G 网络 | 5G 网络 |
|:---|:---|:---|
| **数据通道** | PDN 连接 | PDU 会话 |
| **会话管理对象** | EPS 承载（默认承载 / 专有承载） | QoS Flow（默认QoS Flow / 专有QoS Flow） |
| **QoS 控制粒度** | 承载级（Bearer） | QoS Flow 级（更细粒度，灵活适配业务） |

### 3. 默认会话建立机制
* **4G**：UE 执行 Attach 附着后，**强制建立默认承载**以提供永久 IP 连接。无论是否有业务需求，连接始终维持。
* **5G**：UE 注册网络时**不强制建立默认会话**。PDU 会话根据实际业务需求按需建立。移动性管理与会话管理更好解耦，避免了像 NB-IoT 等低频交互场景下的资源损耗。

### 4. 管理流程差异
| 4G 流程 | 5G 流程 | 差异说明 |
|:---|:---|:---|
| PDN 连接建立 | PDU 会话建立 | 原理一致，概念升级 |
| 专有承载激活/更新/去激活 | PDU 会话修改 | 5G 统一通过会话修改流程实现 QoS Flow 的新增、修改和删除 |
| PDN 去连接 | PDU 会话释放 | 原理一致，释放所有下属 QoS Flow |
| - | **用户面选择性激活/去激活** | **5G新增**：可单独删除用户面而保留信令面，节约无线资源且支持业务快速恢复 |

### 5. 业务连续性支持 (SSC Mode)
* **4G**：仅提供基础的 IP 连续性保障。
* **5G**：引入 `SSC (Session and Service Continuity)` 机制，提供多种模式以适应不同业务需求：
  * **SSC Mode 1**：提供完整 IP 连续性（UPF和IP不变），适用于 IMS 语音等高连续要求业务。
  * **SSC Mode 2**：不提供 IP 连续性（先断后连），适用于缓存视频等允许短暂中断的业务。
  * **SSC Mode 3**：提供短期 IP 连续性（先连后断），适用于 MPTCP 等多径传输应用。

### 总结
5G 会话管理相对于 4G 实现了**控制面集中化（SMF）**、**管理对象细化（QoS Flow）**以及**按需建会话的资源节约机制**。同时通过新增用户面独立激活/去激活流程和灵活的 SSC 模式，更好地支撑了 eMBB、uRLLC、mMTC 等多样化 5G 业务的连续性体验。
