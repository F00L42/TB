/XUDTS消息如何进行重路由



最终回答：


在USC/SPS等STP设备中，XUDTS（Extended Unit Data Signal）消息的重路由遵循**SS7消息重路由**特性，但针对XUDT/XUDTS分段消息有明确的应用限制和性能影响。以下是配置方法及关键注意事项：

### ⚠️ 核心限制（配置前必读）
1. **分段XUDT/XUDTS不支持特定条件重路由**：基于操作码、ACN、被叫号码、主叫号码的MTP/M3UA消息重路由，**不支持分段XUDT消息的组包处理**。
2. **SCCP增强选路限制**：仅支持SCCP 1类消息的XUDT组包处理。
3. **跟踪解析不完整**：XUDT/XUDTS消息在信令跟踪中可能存在解析结果不完整的情况。
4. **性能影响**：若100%流量启用重路由，性能下降约45%；若全部为XUDT类型，性能将进一步下降40%。

---

### 🛠️ 配置步骤（以USC为例）

#### 1. 开启SS7消息重路由软参
```bash
MOD SFPSTP: SPID=P211, MODTYPE=P0, VAL=1;
```

#### 2. 配置链路集服务进程开关
指定需要启用重路由的MTP或M3UA链路集：
```bash
# M3UA链路集示例
MOD M3LKS: LKSNM="你的链路集名称", SRVPROSWT=ROSWT-1, RRT=AP, TTYPE=RD, NRR=10;
```

#### 3. 配置重路由处理规则
定义消息匹配后的转发目标（如第三方平台或新业务节点）：
```bash
ADD RRRULE: RRNM="XUDTS_RRULE", DTYPE=DPC, NI=NM, DSP0NAME="目标信令点名称", PRT0=100, RSWT=G1-1&G2-1&G3-1, OPCFILLWAY=LKOPC;
```

#### 4. 配置匹配条件（根据实际组网选择）
可根据DPC、OPC、GT等条件触发重路由。例如基于DPC：
```bash
ADD RRDPC: RRDPCNM="XUDTS_DPC_COND", RR=10, NI=NM, FO="起始DPC", TO="结束DPC", TTYPE=RRL, RRNM="XUDTS_RRULE";
```

---

### 📌 运维建议
- **避免对分段XUDTS使用操作码/号码匹配**：若业务必须处理分段XUDTS，建议改用DPC/OPC/SI等MTP层条件，或确认消息为非分段类型。
- **性能评估**：现网启用前需进行压力测试，XUDT组包会显著占用SS7U虚拟机/CPU资源。
- **统计开关**：如需统计重路由失败丢弃的XUDTS消息，可开启软参 `P442=1`。
